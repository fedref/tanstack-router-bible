# 19 · 국제화 (i18n)

> 대응 예제: (예제 없음 — 코드 조각으로 설명)
> 📖 공식: [internationalization-i18n](https://tanstack.com/router/latest/docs/framework/react/guide/internationalization-i18n)

## 한 줄 정의 & 언제 쓰나

**locale(언어)을 URL의 어디에 둘 것인가**, 그리고 **언어를 바꿀 때 나머지 URL을 어떻게
유지할 것인가** — i18n에서 라우터가 담당하는 부분은 이 둘이다.

번역 문자열을 관리하는 것은 라우터의 일이 아니다. TanStack Router는 **library-agnostic**
이라 Paraglide, Intlayer, use-intl, i18next 등 어떤 것과도 붙는다. 라우터가 하는 일은
**locale 상태를 URL에 매핑**하는 것뿐이다.

## Path vs Search — 어디에 둘까

| 방식 | URL | 평가 |
|------|-----|------|
| **Path** (권장) | `/ko/about` | SEO에 유리, 사람이 읽기 쉬움, 공유하기 좋음 |
| Search | `/about?locale=ko` | 검색엔진이 별도 페이지로 인식하지 않음 |
| 쿠키/헤더만 | `/about` | URL만으로 언어를 특정할 수 없음 |

공식 문서는 **path param 방식을 권장**한다. 검색엔진이 언어별 페이지를 개별 문서로
인식하고, 링크를 공유했을 때 상대방도 같은 언어로 본다.

## 최소 예제 — optional path param 하나로

핵심은 03장에서 다룬 **선택적 path param `{-$locale}`** 이다. 이 문법 하나로 라우트를
중복 정의하지 않고 기본 언어와 다국어를 동시에 처리한다.

```tsx
// routes/{-$locale}/about.tsx
export const Route = createFileRoute('/{-$locale}/about')({
  component: About,
})

function About() {
  const { locale } = Route.useParams()
  const current = locale ?? 'ko'          // 없으면 기본 언어
  return <h1>{t(current, 'about.title')}</h1>
}
```

이 라우트 하나가 다음을 **전부** 매칭한다.

```
/about        → locale: undefined  (기본 언어)
/ko/about     → locale: 'ko'
/en/about     → locale: 'en'
/ja/about     → locale: 'ja'
```

`{-$locale}` 이 없었다면 `/about` 용 라우트와 `/$locale/about` 용 라우트를 **따로 만들고
컴포넌트를 공유**해야 했다. 그 중복이 사라진다.

## locale 검증하기

아무 문자열이나 locale로 들어올 수 있으므로 걸러야 한다. `/zz/about` 이 유효한 페이지처럼
동작하면 곤란하다.

```tsx
const LOCALES = ['ko', 'en', 'ja'] as const
type Locale = (typeof LOCALES)[number]

function isLocale(v?: string): v is Locale {
  return LOCALES.includes(v as Locale)
}

export const Route = createFileRoute('/{-$locale}/about')({
  beforeLoad: ({ params }) => {
    if (params.locale && !isLocale(params.locale)) {
      throw notFound()          // 12장 — 잘못된 언어는 "없음" 처리
    }
  },
  component: About,
})
```

**`notFound()` 를 쓰는 것이 적절하다.** 에러가 아니라 "그런 페이지는 없다"가 맞는 표현이다.
루트 레이아웃에 한 번 걸어 두면 하위 전체가 보호된다(06장 pathless 가드와 같은 구조).

## 언어 전환 — 나머지 params 유지하기

언어를 바꿀 때 **보고 있던 페이지에 그대로 머물러야** 한다. `params` 에 업데이터 함수를
넘기면 기존 값을 유지한 채 locale만 갈아끼울 수 있다.

```tsx
<Link
  to="/{-$locale}/blog/{-$category}/$slug"
  params={(prev) => ({ ...prev, locale: 'en' })}
>
  English
</Link>

// 기본 언어로 돌아가기 — undefined 를 넣으면 세그먼트가 사라진다
<Link
  to="/{-$locale}/blog/{-$category}/$slug"
  params={(prev) => ({ ...prev, locale: undefined })}
>
  한국어
</Link>
```

`(prev) => ({ ...prev, … })` 패턴이 중요하다. `params={{ locale: 'en' }}` 으로 쓰면
`category` 와 `slug` 가 사라져 타입 에러가 난다.

재사용할 언어 전환 컴포넌트는 이렇게 만든다.

```tsx
function LocaleSwitcher() {
  const { locale } = useParams({ strict: false })

  return (
    <nav>
      {LOCALES.map((l) => (
        <Link
          key={l}
          to="."                                   // 현재 라우트 유지
          params={(prev: any) => ({ ...prev, locale: l === 'ko' ? undefined : l })}
          activeProps={{ className: 'font-bold' }}
        >
          {l.toUpperCase()}
        </Link>
      ))}
    </nav>
  )
}
```

## `rewrite` 로 locale을 URL 층에서 분리하기

Paraglide처럼 **자체 URL 로컬라이즈 함수**를 제공하는 라이브러리와 붙일 때는, 16장의
`rewrite` 옵션이 더 깔끔하다. 라우트 트리에는 locale이 아예 등장하지 않는다.

```tsx
import { deLocalizeUrl, localizeUrl } from './paraglide/runtime'

const router = createRouter({
  routeTree,
  rewrite: {
    input: ({ url }) => deLocalizeUrl(url),    // 들어올 때: /en/about → /about
    output: ({ url }) => localizeUrl(url),     // 나갈 때:   /about → /en/about
  },
})
```

**라우트는 `/about` 만 알면 되고**, locale 접두사는 rewrite 층이 붙였다 뗀다. 라우트
파일에 `{-$locale}` 을 넣지 않아도 되므로 트리가 단순해진다.

| 방식 | 장점 | 단점 |
|------|------|------|
| `{-$locale}` param | locale이 params로 명시적으로 보임 | 모든 라우트 경로에 `{-$locale}` 이 붙음 |
| `rewrite` | 라우트 트리가 깨끗함 | locale이 params에 없어 `useParams` 로 못 읽음 |

`rewrite` 를 쓸 때 현재 언어는 i18n 라이브러리의 런타임에서 읽는다(예: Paraglide의
`getLocale()`).

## `<html lang>` 속성

접근성과 SEO 모두에 필요하다. locale이 바뀔 때마다 갱신한다.

```tsx
function RootLayout() {
  const { locale } = useParams({ strict: false })
  const current = locale ?? 'ko'

  useEffect(() => {
    document.documentElement.lang = current
  }, [current])

  return <Outlet />
}
```

SSR이라면 `head` 옵션이나 `shellComponent` 에서 서버 렌더 시점에 넣는 편이 낫다(16·17장).

## 흔한 실수 / 함정

**1. 언어별로 라우트 파일을 복제한다**
`about.ko.tsx`, `about.en.tsx` 처럼 만들면 라우트가 언어 수만큼 늘어난다. `{-$locale}`
하나로 끝난다.

**2. 언어 전환 시 `params` 를 객체로 통째로 넘긴다**
```tsx
params={{ locale: 'en' }}                        // ❌ 다른 params 가 날아간다
params={(prev) => ({ ...prev, locale: 'en' })}   // ✅
```

**3. locale 검증을 하지 않는다**
`/zz/about` 이 빈 화면이나 기본 언어로 조용히 동작한다. `beforeLoad` 에서 `notFound()` 를 던진다.

**4. 기본 언어에도 접두사를 붙인다**
`/ko/about` 과 `/about` 이 **둘 다 살아 있으면 중복 콘텐츠**가 되어 SEO에 불리하다.
기본 언어는 `undefined`(접두사 없음)로 통일하고, `/ko/about` 이 들어오면 `/about` 으로
리다이렉트하는 편이 낫다.

**5. `hreflang` 태그를 빠뜨린다**
검색엔진에 언어별 대체 페이지를 알리려면 `<link rel="alternate" hreflang>` 이 필요하다.
SSR에서 `head` 옵션으로 넣는다(16장). CSR만으로는 크롤러가 읽지 못한다.

## 🔗 시너지

- **03장 선택적 path param** — `{-$locale}` 이 이 장의 전부라고 해도 과언이 아니다.
  그 문법을 모르면 라우트를 언어 수만큼 복제하게 된다.
- **06장 beforeLoad 가드** — locale 검증은 인증 가드와 정확히 같은 구조다.
- **12장 notFound** — 잘못된 locale은 에러가 아니라 "없음"이다.
- **16장 `rewrite`** — locale을 라우트 트리에서 완전히 걷어내는 대안.
- **13장 search 미들웨어** — locale을 search로 관리한다면 `retainSearchParams(['locale'])`
  로 전 페이지에 유지시킬 수 있다. 다만 path 방식을 권한다.
